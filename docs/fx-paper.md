# FX のペーパー運用（前向きの記録）

AI・売買ルール・基準を、**その時点の本物の値段** で判断・約定させて記録します（仮想の約定）。
**注文は出しません。** 実際の売買（[fx-live.md](fx-live.md)）とは独立で、ペーパー運用を止めても実際の売買は続きます。

AI の判断は、過去のデータでは試せません。AI はモデルが学習した期間の値動きを知っているので、過去で試すと先読みになるためです。
そこで、これから先を前向きに記録して比べます。

## 口座

| 口座 | 判断 |
|---|---|
| `ai` | AI（拡張パーツ）。枠の中で、通貨ペア・向き・リスクの割合・損切り・利確を自由に決める |
| `rule_hourly_breakout` | 1時間足の突破（過去の検証の `hourly_breakout_20` と同じ決まり。損切り50 pips） |
| `buy_and_hold` | ドル円を買って持つ（損切り100 pips） |
| `no_trade` | 一切売買しない |
| `carry_trend_<通貨ペア>` | 金利差＋流れ（過去の検証で一番有力だった候補）を4通貨ペアで。同じ数値のまま、新しいデータで確かめる（1回100通貨・損切り150 pips） |

どの口座も1万円から始め、同じ時刻・同じ値段・同じコスト（API 手数料 0.002%、ずれ 0.1 pips）で並べます。
スワップは、各通貨の短期金利の差から見積もります（検証と同じ。業者の取り分0.5%）。

## 枠（`core/fx/frame.py`）

AI の判断もルールの判断も、ここを通らなければ実行しません。通らなかった判断は、理由と一緒に記録します。

- 選べる通貨ペアは USD_JPY / EUR_JPY / GBP_JPY / AUD_JPY
- 新規には必ず損切りを付ける（10〜150 pips）。利確を付けるなら、損切りの幅の半分以上
- 数量は「1回の損切りで失う割合」から逆算する。上限はリスクの度合い（既定は medium: 1%・5倍まで・1日 −4% で停止）
- 同時に持つ建玉は1つ。向きを変えるなら、いったん閉じる
- スプレッドが 1 pip を超える時、1日の損失の上限に届いた日、キルスイッチ（`state/KILL_fx_paper`）が在る時は、新規を作らない
- 閉じる判断は、いつでも通す

## 動かす

```bash
make paper                                  # 1回進める
python scripts/fx_paper.py --status         # 口座の状態を見るだけ
python scripts/fx_paper.py --risk small     # リスクの度合いを変える（既定は FX_PAPER_RISK、無ければ medium）
```

Cloud Run では、Cloud Scheduler が月〜土の毎時1分に呼びます（[cloud-run.md](cloud-run.md)）。市場が閉まっていれば何もしません。
結果は操作盤の「FX ペーパー」で見られます。記録は `state/fx_paper.jsonl`（追記のみ）です。

## 振り返り（改善の種）

AI の判断には、根拠（理由・確信度・想定する期間・リスク）と、**そのとき AI が見ていた入力** をそのまま記録します。
ルールの口座は、売買しなかった回も含めて毎回、**決まり（文章と版）と、そのとき見た数字**（終値・50日平均・金利差・直近20時間の高値と安値など）を記録します（`logic`）。
`scripts/fx_paper_review.py` は、判断ごとに根拠と、判断のあと1・4・24時間の値動き（pips）を並べます。

```bash
gcloud storage cp gs://<プロジェクト>-algo-trading-state/state/fx_paper.jsonl .
python scripts/fx_paper_review.py --log fx_paper.jsonl
```

見るのは、根拠の偏り（毎回同じ理由で見送っていないか）と、見送った回にコストを大きく超える値動きがどれだけあったかです。
値動きは結果論なので、1回ごとの当たり外れでプロンプトを変えないでください。変えたら、変える前の記録とは別物として比べます。

## 費用

AI（Gemini 2.5 Flash-Lite）は1回 $0.002 ほどです。1時間に1回なら月に約 $1 で、月の上限（$5）に含まれます。

## 読み方

- 取引が30件に満たないうちは、運の範囲です
- AI と他の口座を比べること自体が多重比較になります。1つの月の結果で決めないでください
- 増額の判断は、取り置いた検証期間と同じく、事前に決めた条件（[operations.md](operations.md)）で行います

## 実際の約定（読むだけ）

人が GMOコインのアプリで発注した約定・建玉・資産を、ペーパー運用と一緒に15分ごとに読んで `state/fx_live.jsonl` に記録します
（`scripts/fx_live_sync.py`）。約定の値段と、その1分足の始まりの買値・売値との差（ずれ、pips）も残し、ペーパー運用の想定（0.1 pips）と比べます。
画面は「FX → 実際の約定」。

- 約定の履歴は API の都合で直近1日分しか取れないので、1日1回以上は動かす
- API キーに、約定・建玉の **照会** の権限が要ります（注文の権限は要りません）。足りないと `ERR-5012` になり、画面に出ます

## 短期売買（ペーパー）

長期の判断する者（AI・金利差＋流れ）とは別に、見張り役が値段1つずつ（1秒に約10回）で判断する短期売買を、
仮想の約定で回しています（`application/fx_scalp.py`。**実際の注文は出さない**）。うまくいきそうなら、実運用に
展開するかを決めます。画面は「取引 → 短期売買（ペーパー）」。

| 口座 | 決まり（scalp-v3） |
|---|---|
| 短期・逆張り（scalp_fade） | 60秒で5 pips 以上動いたら反対に1,000通貨。利確3 pips・損切り5 pips・最長10分 |
| 短期・順張り（scalp_follow） | 同じ動きで同じ向きに1,000通貨。利確5 pips・損切り3 pips・最長10分 |

- 約定は実運用と同じく、買いは売値（ask）、売りは買値（bid）で、スプレッドと手数料（0円）込み
- スプレッドが1 pip を超えるときは建てない。建玉は口座ごとに1つ。閉じたあと2分は建てない
- 重要な経済指標の発表（その通貨ペアの通貨のもの）の前10分・後15分は、新しく建てない（下の「経済指標の予定」）
- 損切り・利確は、その値段ちょうどで約定したことにする（実際はずれることがあるので、少し甘め）
- 記録は `state/fx_scalp.jsonl`。届いた値段そのものも `state/ticks/日付/時.csv.gz` に残す
  （あとで別の決まりを、同じ値動きで試し直すため）
