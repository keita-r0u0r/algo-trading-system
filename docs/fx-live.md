# FX の自動売買（実際のお金）

判断する者（AI・金利差＋流れ（ドル円））が、**実際の口座の状態**（実際の建玉・評価額）を見て判断し、GMOコインの実際の口座で **小さく** 売買します。
**ペーパー運用（シミュレーション）とは独立** です。ペーパー運用を止めても、実際の売買は続きます（実際の売買を止めるのはキルスイッチと `fx_live_enabled`）。

**方針**: 止めるのは、致命的な損失（入金額を超える損＝不足金）のおそれがあるときだけ。持ち続ける理由が無くなった建玉は閉じる（ルールの条件が崩れた、AI が閉じると判断した、損切りの値段に届いた）。
**実際にお金が動きます。** 結果は保証されず、損をすることがあります。投資の助言ではありません。

## 実際に売買する判断する者

| 口座 | 実際の注文 |
|---|---|
| AI | 実際の建玉と評価額を見て判断する。建てるときは、根拠の強さに応じてリスクの割合（1回の損切りで資金の最大5%）を選び、そこから逆算した数量（**1,000通貨まで**）を成行で建て、損切り・利確を GMOコイン側に置く。目標（1か月で1.5倍）も AI に渡す |
| 金利差＋流れ（ドル円・ユーロ円・ポンド円・豪ドル円） | 同上（損切り150 pips）。通貨ペアごとに別の口座として持つ。数量は流れの強さ（終値が50営業日の平均を何%上回るか。2%で満額）に応じて、資金の1.5〜5%のリスクから逆算 |
| ハーネス＋決まり（新しい作り） | 建てる・閉じるを、特徴量（`application/fx_features.py`）と決まり（`application/fx_setups.py`）が決める。流れの中の押し目だけを建て、損切りは1時間足の揺れから。比べるあいだは **300通貨まで**・リスク1% |

### 今の作り（AI が判断）と新しい作り（ハーネス＋決まり）を並べて比べる

- 画面の「自動売買」で、2つの作りをそれぞれ ON/OFF できます（`state/fx_settings.json`）。OFF にした作りは新しく建てず、持っている建玉の決済だけ続けます
- 新しい作りでは、AI（Gemini）や Jev（TypeSafe）に聞けるのは2つだけです。向き・数量・損切りは変えられません
  - **見送るか**: `off`（聞かない）・`shadow`（聞いて記録だけ。既定）・`veto`（見送ると言ったら建てない）
  - **決済の手法**（`application/fx_exits.py`）: 決まった1つか、建てるときに AI / Jev が選ぶ
    - `target`: 損切りと利確（3倍）だけ
    - `breakeven`: 損切り幅の1.5倍に出たら建値へ、利確3倍
    - `percent_peak`: 最大の含み益の半分を失ったら降りる（揺れを見ないので比べるために残す）
    - `chandelier`: 最高値から1時間足の揺れの一定倍で追いかける（LeBeau / Elder）
    - `structure`: 直近の5分足の安値・高値の外で追いかける
- 建てたあとの決済は決まりが持ちます。見張り役は、決まりが最後に出した「降りる線」を割ったら回を起こし、その回では AI を呼びません
- 画面の「判断する者の比較」に、勝ちの大きさ（平均の勝ち ÷ 平均の負け）・乗った含み益を残せた割合・Jev / AI の見送りの答えとその取引の結果が並びます
- Jev のキーは Secret Manager の `typesafe-api-key`。1回 約 $0.00004、使った分は `state/jev_usage.jsonl`

### 数量の上限と、AI の見直しの提案

- 画面の「自動売買」で、判断する者ごとに **数量の上限**（100通貨単位）と **1回の損切りで失ってよい資金の割合の上限** を変えられます。全体の枠（1口座1,000通貨・5%）は超えられません
- 既定: AI と金利差＋流れは 1,000通貨・5%、ハーネス＋決まりは 300通貨・1%（決まりは上限のリスクいっぱいで建て、数量は損切り幅から逆算）
- AI は平日の朝7時以降に1日1回、判断する者ごとの成績（平均の勝ち・負け、連敗、資金に対する最大の落ち込み）を見て、見直しを提案します（`state/fx_sizing_proposals.jsonl`）。決済が10回未満の判断する者は変えません
- **提案は自動では効きません。** 画面で「この提案を適用する」を押したときだけ変わります（答えは `state/fx_sizing_answers.jsonl`）。「今すぐ AI に提案させる」でも出せます（1回 約 $0.003）

- 判断する者が閉じると判断したら、実際の建玉を成行で決済します
- 損切り・利確に掛かったときは、GMOコイン側に置いた注文で決済されます（システムが止まっていても効く）
- 判断は記録に `live_decision` として残ります（ペーパーの判断とは別）
- 15分ごとのペーパー運用の回に、まとめて行います（`scripts/fx_live_trade.py`）

## 安全装置

| 装置 | 動き |
|---|---|
| 有効にするスイッチ | `infra/terraform.tfvars` の `fx_live_enabled = true` のときだけ注文を出す。既定は false（何をするかを記録するだけ） |
| キルスイッチ | 画面「FX → 実際の約定」のボタン。入れると新しい注文を出さない（決済は出す） |
| 数量の上限 | 1口座1,000通貨まで（利用者が決めた）。取引余力（必要な証拠金の1.2倍）に足りない分は減らし、100通貨に届かなければ建てない |
| 建玉は1口座1つ | 持っている間は新しく建てない |
| 致命的な損失を防ぐ | 証拠金維持率が110%を切ったら（評価額が0以下でも）、全部の建玉を成行で決済し、キルスイッチを入れる。急変でロスカット（100%）を飛び越え、入金額を超える損（不足金）が出るのを防ぐ |
| 1日の損失の上限 | **既定では使わない**（利用者の方針: 致命的でない損失では止めない）。`LiveConfig.daily_loss_limit` で入れられる |
| 証拠金の余裕 | 取引余力が、必要な証拠金（新規は20倍）の1.5倍に足りなければ建てない |
| 損切りを置けない | 3回試してもだめなら、その建玉を成行で決済し、キルスイッチを入れる |
| 約定を確かめられない | キルスイッチを入れる（アプリで建玉を確かめる） |
| 二重発注の防止 | 判断ごとに一意な顧客注文ID |
| 発注用のキーを分ける | 照会用とは別のキー（gmo-fx-trade-api-key / secret）。照会用の部品には発注の機能が無い（テストで固定） |
| IP の制限 | クラウドの出口の IP を固定し、発注用のキーをその IP だけに制限する |

## 始め方

1. 出口の IP を固定する（有料。固定 IP と Cloud NAT で月に数百円の見込み）

   ```hcl
   # infra/terraform.tfvars
   fx_live_egress = true
   ```

   `make infra-apply` のあと、`tofu -chdir=infra output egress_ip` で IP を確かめる

2. GMOコインで **発注用の** API キーを作る。権限は照会と注文（入出金は付けない）。**IP の制限に 1. の IP を登録する**
3. キーを Secret Manager に置く（ターミナルで。値は画面に出ない）

   ```bash
   gcloud secrets create gmo-fx-trade-api-key --replication-policy=automatic
   read -rs "V?発注用の APIキー: "; echo; printf %s "$V" | gcloud secrets versions add gmo-fx-trade-api-key --data-file=-; unset V
   gcloud secrets create gmo-fx-trade-api-secret --replication-policy=automatic
   read -rs "V?発注用のシークレット: "; echo; printf %s "$V" | gcloud secrets versions add gmo-fx-trade-api-secret --data-file=-; unset V
   ```

4. 外国為替FX の口座に資金がある（取引余力が見える）ことを、画面「実際の約定」で確かめる
5. `fx_live_enabled = true` にして `make infra-apply`

止めるときは、画面のキルスイッチ（すぐ効く）か、`fx_live_enabled = false` で `make infra-apply`。

## 見張り役（常時）: 定期判断と随時判断

実際の売買は **見張り役**（`scripts/fx_watch.py`）が、その中で判断して発注します。GMOコインの値段の配信を受け取り続け、
1秒ごとに条件（`application/fx_watch.py`）を確かめます。

- **随時判断**: 次のどれかが起きたら、**その場で（数秒で）** 判断して発注する。AI も必ず呼ぶ
- **定期判断**: 5分ごとに判断する。AI は15分ごと（それ以外は前回の AI の判断を使う）

| 条件 | 既定 |
|---|---|
| 急変 | 5分で ±15 pips 以上 |
| 建玉が損切り・利確に近い | あと3 pips 以内（ペーパーと実際の建玉） |
| 時間帯の切り替わり | 17:00（ロンドン）・22:00（ニューヨーク）。冬時間の目安 |
| 建玉の見直し（実際の建玉） | 含み損が損切りまでの1/3・2/3、含み益が利確までの1/3・2/3（線ごとに1回） |
| 含み益の目減り | 含み益の最高が5 pips 以上になったあと、その40%を失った（最高を更新したら、また起こす） |

起こした回どうしは2分あける（判断の回が重ならないように）。AI は建玉を持っているあいだ、毎回「今この値段で
新しく建てるか（would_open_now）」で見直し、建てないなら閉じる（fx-v8）。画面の概要には、建玉ごとに
「次に AI が見るとき」（定期・損切り/利確の手前・見直しの線・目減りの線・急変・時間帯）を出す。

### 相場の特徴量（ハーネス）と、予想の見張り

`application/fx_features.py` が1分足から、裁量のトレーダーが見る要素を計算する（AI にも機械の判断にも同じ数字を
渡すための部品）: 15分・1時間・4時間・24時間の動きと、ふだんの揺れ（ATR）の何倍か（1倍未満は揺れの範囲）、
1分・5分・1時間足の ATR・RSI・移動平均・ボリンジャー、今日・前日・4時間の高値と安値、キリの良い値段、時間帯、日足。

AI（fx-v9）は建てるときに、取引の形（setup）と、機械が確かめられる予想（根拠が崩れる値段・目標・保有の目安）を出す。
見張り役は、根拠が崩れる値段を越えた・目安の半分で目標の1/4も進んでいない・目安を過ぎても届かない、のどれかで AI を起こす。

### AI と相談する・メモを渡す

概要の「AI と相談する」で、今の建玉・最近の判断・経済指標の予定を渡して質問できる（答えるだけで、注文は出さない）。
「AI にメモを渡す」に書いたメモは、期限まで毎回の AI の判断に `user_notes` として入る（`state/fx_notes.jsonl`）。

段取りは部品になっていて、ジョブと見張り役は同じものを呼びます（AI は判断の材料を返すだけ。枠の確認・数量・損切りの必須・
発注・約定の確認・致命的な損失での全決済は、すべて決まったロジック）。

| 部品 | 役目 |
|---|---|
| `core/fx/frame.py` | 枠（通貨ペア・損切り10〜150 pips・数量・建玉1つ） |
| `application/fx_live_trade.py` | 判断 → 注文の計画（上限1,000通貨・証拠金の余裕・致命的かどうか） |
| `interfaces/fx_live.py` | 発注・損切り/利確の注文・約定の確認・失敗したら決済してキル |
| `interfaces/fx_runtime.py` | 1回分の段取り（材料を集める → 判断 → 計画 → 発注 → 記録） |
| `infrastructure/gcs_sync.py` | 記録を Cloud Storage と同期（追記分だけ、上書きしない） |

- 直前に起こしてから5分は起こさない。回の途中は次の回を起こさない
- 起こした理由は AI に渡し、判断の記録にも残る（`trigger`）
- 見張り役は us-central1 の e2-micro（無料の枠）。外に出る IP を固定してあり（`tofu output watcher_ip`）、
  **注文用のキーの IP 制限に、この IP も足す** 必要がある
- 1分ごとに生きている印（`state/fx_watch.json`）を書く。これが5分以内なら、ジョブ（5分ごと）はペーパーだけを担当する。
  見張り役が止まっていたら、ジョブが代わりに実際の売買をする（Cloud NAT の固定 IP 34.85.60.96 から）
- `infra/terraform.tfvars` の `fx_watch_enabled = true` で動く
- 画面の上に「見張り: 動いている / 止まっている」、システムの画面に起こした記録

## 経済指標の予定

GMOコインの API にはニュースや経済指標が無いので、公開の週間カレンダー（Forex Factory の JSON。キー不要）から
今週の予定（時刻・通貨・指標名・重要度・予想・前回）を取る（`infrastructure/econ_calendar.py`）。

- 判断の回が1時間ごとに取り直し、`state/fx_calendar.json` に置く。取れなかったときは前に取った分を使い、売買は止めない
- AI には、この先12時間・直前2時間の、通貨ペアに関係する発表（重要度が中以上）を `market.economic_calendar` で渡す（fx-v6）。
  発表の直前は値段が飛びやすいこと、発表直後の急変は発表による動きとして扱うことを指示している
- 短期売買（ペーパー）は、重要な発表の前10分・後15分は新しく建てない（`application/fx_calendar.py` の `quiet_reason`）
- 画面の概要（常時監視の下）に、この先24時間の予定を出す。3時間を超えて取れていなければ、健康診断が注意を出す
- 実際の口座の機械の判断（金利差＋流れ）は、今は予定を見ない（結果を見てから相談する）

## 健康診断と、反映したあとの確認

動いているはずのものが本当に動いているかは、`application/fx_health.py` が記録から機械的に確かめます。
画面（左の帯と、概要のいちばん上）と、反映後の確認が同じものを使います。

| 確かめること | 異常とみなすとき |
|---|---|
| 見張り役 | 生きている印が無い・値段が3分届いていない・判断の回が15分実際の口座に届いていない |
| AI | 判断の回が15分無い・AI が20分実際に判断していない（呼べなかった理由も出す） |
| ロジック | 判断の回が15分無い・見た数字の記録が無い |
| 口座 | 照会できない（キー・IP の制限）・直近1時間のエラー・キルスイッチ |
| ペーパー運用 | 止めている（お知らせだけ。実際の売買には関係ない） |

市場が閉まっている間（土曜 7:00〜月曜 7:00）は、止まっているとは言いません。

反映したら、必ず確認します。新しい版の見張り役が起動し、AI とロジックが判断して実際の口座に届くまで待ち、
できなければ失敗で終わります（AI を呼べなかったら、その理由を出してすぐ失敗）。

```bash
make verify V=<反映した版>   # 例: make verify V=28416eb
make health                  # 今の健康診断だけ
```

見張り役は起動したらすぐ「これから担当する」印を書き、判断の回のたびに書き直します。ジョブは、起動5分以内か、
5分以内に実際の口座に届いた見張り役がいれば、実際の売買を譲ります（作り直しの前後に、二重に建てないように）。
