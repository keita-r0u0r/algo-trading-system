# リリースの手順（反映・段階・戻し方）

実際のお金で動いているので、**うまくいっていた部分を壊さない・壊れたらすぐ戻せる** ことを優先する。

## 1. 出す前

- PR に `CHANGELOG.md` の項目（`## #<PR番号> · <日付> · <題>`。売買・画面・費用・影響のうち変わったもの）を足す
- テストと CI が通ってからマージする
- 次の時間帯には反映しない。見張り役の作り直しで2〜5分止まるため
  - 重要な経済指標の前後30分（画面の「経済指標の予定」）
  - 朝7〜9時（スプレッドが広く、判断が通らないので確かめにくい）

## 2. 新しい判断する者・新しい決まりは、段階を踏む

判断する者ごとに段階がある（画面の「自動売買 → 売買の作り」。`state/fx_settings.json`）。

| 段階 | 何をするか |
|---|---|
| 止める（off） | 新しく建てない。持っている建玉の決済は続ける |
| 記録だけ（shadow） | 実際の口座と同じ材料・同じ枠で判断するが、注文は出さない。通った判断を仮の建玉として記録し、損切り・利確・判断での決済まで結果を残す（`state/fx_shadow.jsonl`）。画面の「判断する者の比較」に成績が出る |
| 本番（live） | 実際に注文を出す |

- **新しい判断する者は「記録だけ」で入れる**。数日〜1週間、成績（平均の勝ち÷平均の負け・合計の R）を見て、本番に上げる
- 本番に上げるときも、数量の上限を小さく始める（画面の「数量の上限」）
- 既にある判断する者の決まりを大きく変えるときは、古い決まりを消さずに新しい判断する者として並べ、記録だけで比べる

## 3. うまくいかなくなったら（まず設定で戻す）

1. **画面で、その判断する者を「止める」か「記録だけ」にする**。反映し直さないので、すぐ効く（次の回、5分以内）。
   持っている建玉は、止めても決済まで面倒を見る
2. それで足りないとき（画面が開かない・全体がおかしい）だけ、**前の版に戻す**:

```bash
make rollback          # リリースログで確認が通った、今より前のいちばん新しい版に戻す
make rollback TO=333b491
```

`make rollback` は、次の順に進む。
- 戻す先と、戻すと無くなる変更（PR）を表示する
- **戻す先の版が知らない判断する者の建玉** があれば警告する（戻すと誰も決済しない。GMOコイン側の損切りだけが効く）
- 計画（`tofu plan`）を見せて、`y` を押したときだけ反映する
- 反映したら確認（`fx_verify.py`）し、リリースログに残す

## 4. 前の版に戻しても壊れないための決まり（コードを書くとき）

- **記録と設定の項目は、足すだけにする**。消したり意味を変えたりしない。古い版は知らない項目を無視して動く
  （`state/fx_live.jsonl`・`fx_settings.json`・`fx_shadow.jsonl` など）
- **判断する者の名前を変えない・使い回さない**。新しい決まりは新しい名前で足す
- **建玉は、判断する者が消えても誰かが見る**。今の版が知らない判断する者の建玉は、健康診断が「管理していない建玉」（赤）として出す
- 設定の読み方は、壊れた値・知らない値を既定に戻し、売買を止めない（`fx_filter.parse_settings`）

## 5. 反映したあと

- `make verify V=<版>` が、新しい版の見張り役が判断して口座に届くまで待ち、結果をリリースログ（`state/releases.jsonl`）に残す
- 画面の「システム → リリースログ」で、本番の版・確認の結果・入った変更を見る。概要の上にも本番の版が出る
