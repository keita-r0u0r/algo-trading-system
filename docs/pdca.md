## 1周目（2026-10-21〜22）

### Plan（このときの計画）

- FX（GMOコイン）を1万円から。1か月ごとに「資産が増えたか」で評価する
- 売買ルールは実データ（2023-10〜2026-06）で検証し、最後の3か月は取り置く
- AI は、枠の中で判断させ、前向きのペーパー運用で記録する

### Do（やったこと）

| | 内容 |
|---|---|
| 検証 | 1分足の頻繁な売買6通り、取引の少ない3通り、金利差1通り（ドル円）。同じ3通りを4通貨ペアに広げた（数値は変えない） |
| リスク | 小・中・最大で数量だけ変えて比べた |
| AI | ペーパー運用を GCP で4回（fx-v1）。前提文を FX 専用に分けた（fx-v2。手元で1回） |
| 基盤 | Cloud Run（IAP・OAuth）、1時間ごとのジョブ、OpenTofu。使わない間は消す |

### Check（分かったこと）

| 問い | 答え | 根拠 |
|---|---|---|
| 1分足で頻繁に売買して勝てるか | **勝てない** | 1取引の損失 ≒ コスト（往復約1 pip）。コスト前の優位性はほぼ0 |
| 取引を減らせば勝てるか | **偶然と区別がつかない** | 4通貨ペアを合わせても t 値は −0.5〜0（london / hourly）、日足は −1.9 |
| ドル円で少しプラスだったのは本物か | **たまたま** | 同じルールを他の3通貨ペアで試すと、プラスとマイナスが混ざる |
| 何が一番良かったか | **買って持つだけ**（月 +0.93%、t = +1.86） | この3年の円安とスワップ（仮定）。ルールの力ではない |
| リスクを上げれば増えるか | **増えた月の割合は変わらない** | 振れ幅だけが大きくなる。1日の損失の上限がロスカットより先に効く |
| AI は判断できるか | **まだ分からない** | fx-v1 は4回とも見送り（共通の前提文の慎重さに引っ張られた）。fx-v2 は判断するが、件数が0 |

試行回数（同じデータで試した候補 × 通貨ペア）: **26**。偶然でも出る t 値の目安は約2.0。

見つけて直した不具合:

- **月ごとの評価で、戦略が過去の足を知らずに始まっていた**。日足20日の突破は、33か月×4通貨ペアで12件しか取引していなかった。
  直前40日を「助走」として見せるようにした（`FxConfig.trade_from`）。直したあとは125件
- 初回の `make infra-apply` で、OpenTofu の警告文を版として読み、存在しないイメージで Cloud Run を作ろうとした
- 別のブランチで、メールアドレス入りの `terraform.tfvars` がコミットに入りかけた（push の失敗で気づいた）。
  **テストで止めるようにした**（`tests/test_repo_hygiene.py`）

### Act（次の周で変えること）

1. **値動きだけのルールを足すのは、いったん止める。** 26通り試して何も出ていない。足すほど偶然の当たりを拾いやすくなる
2. **唯一プラスだった「持つこと」（キャリー）を、正しく測る。** スワップは仮定のまま。実際のスワップの値を取り、
   2024年8月のような急な円高でどれだけ失うかを含めて評価する。そのうえで、守り（金利差・値動きの大きさでの絞り込み）を1〜2通りだけ試す
3. **AI（fx-v2）は前向きに記録を貯める。** 平日の日中だけ動かし、4週間で30回ほどの判断を目標にする。費用は月 $1 前後
4. **長く持つルールは、月ごとではなく取引ごとに評価する。** 月の終わりで手仕舞うと、数週間持つルールの成績が切られる
