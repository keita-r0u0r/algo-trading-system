# algo-trading-system

国内株と FX の売買ルールを **検証** し、少額（1万円から）で **安全に運用を試す** ための環境です。研究用です。

> **注文は出しません。** 売買候補を出し、人が証券会社・FX業者のアプリで発注し、約定をここに記録します。
> 出力は検証ツールの結果であって、**投資助言ではありません。** 結果は保証されません。
> 優位性のある売買ルールは、まだ見つかっていません（[今わかっていること](#今わかっていること)）。

## 今わかっていること

**検証の結果、優位性があると言える売買ルールはまだ見つかっていません。**

### 国内株（日足、実データ）

条件: 資金1万円、1株単位、最大5銘柄、単元未満株の追加スプレッド片道0.3%（仮定）。
開発期間 2025-01-15〜2026-02-18（268営業日）。

- 候補5系統15通り（モメンタム、短期逆張り、低ボラティリティ、ブレイクアウト、地合いフィルタ付き保有）のうち、
  **「15通り試せば偶然でも出る水準」（年率 Sharpe 1.75）を超えたものは無い**。最良は 0.42
- 同じ期間、市場の等ウェイト平均（取引できない参考値）は +34.5%。ほとんどの候補が届かない
- 成績が実装の細部で大きく動いた（数量の計算を直しただけで +24% → +3%）。雑音を見ている兆候
- 最後の100営業日はロックボックス（最後に一度だけ使う検証用期間）として取り置いている。
  最良候補には未使用。`regime_hold` については、操作盤の確認中に一度参照してしまった

### 見つけて直した偏り

戦略が「買える銘柄か」を **調整後の価格** で判定していた。調整後の価格は、後から起きた株式分割で
過去が割り引かれるので、当時は買えなかった銘柄を買える扱いにしていた。分割は上昇のあとに起きやすく、
将来を知っているのと同じ偏りになる。**ある候補が +139% から +4% に落ちた。**

このルールは `liquid_universe` ではテストで守らせていたが、戦略が使う `affordable_symbols` では破られていた。
いまは両方をテストで固定している。**一見すごい成績が出たら、まずバグと先読みを疑う。**

### FX（分足、ダミーデータ）

ダミーデータは値動きの性質をこちらで決めて作るので、**成績は勝てる根拠にならない**。確かめたのは仕組みだけ。

- 性質の無いデータで、どの戦略も勝ちと判定されない / 平均回帰には逆張りが、トレンドには順張りが勝つ /
  スプレッドを上げると勝ちが減る — すべて OK
- 1万円で最小1,000通貨（実質約15倍）だと、ロスカットより先に **資金が約7,500円を切って新しい建玉を作れなくなる**

## 先に知っておくべきこと

### 1. 単元の壁

国内株は100株単位です。1銘柄に10万円しか割けないなら、**株価1,000円を超える銘柄は1単元も買えません**。
資金1万円なら、100株単位で買えるのは全銘柄の約2%です。

単元未満株（1株単位）なら、1万円を3銘柄に分けても約80%が買えます（`--lot-size 1`）。
ただし、単元未満株は証券会社が定める時刻・価格で約定し、スプレッドも広めです。追加スプレッドの既定値
（片道0.3%）は **仮定** で、実測に置き換える前提です。

買えない銘柄が多いと、検証結果は実質的に低位株だけのものになり、市場全体の性質とは違います。
`scripts/run.py` は毎回、その資金で母集団の何割が買えるかを表示します。

### 2. コストの支配力

株価1,000円の銘柄の呼値は1円。最良気配を取りに行くだけで往復0.2%。年10回転させれば年2%が消えます。
FX のスキャルピングは月に1,000回以上取引するので、スプレッドが0.2 pips 違うだけで期待値が大きく動きます。

`--costs all` で楽観・標準・悲観の3通りを並べられます。
**前提を変えて結論が反転するなら、それは優位性ではなくコスト仮定です。**

## 設計

### 層と FCIS

```
    interfaces   →   application   →   core
   （CLI・GUI・組み立て）（手続き）     （純粋関数）
                          ↑
                    infrastructure
                 （Port の実装を注入する）
```

| | Functional Core | Imperative Shell |
|---|---|---|
| 場所 | `core/**` | `application/**`, `infrastructure/**`, `interfaces/**` |
| できること | 純粋関数、不変データ、計算 | ファイル・API・時刻・GUI |
| 禁止 | `datetime.now()`、I/O、乱数、引数の書き換え | 判断そのもの |

`core` は他のどの層も import しません。`application` は自分が定義した Port にだけ依存し、
SQLite も GCP も知りません。この制約は `tests/test_architecture.py` が AST 解析で機械的に検査します。

純粋であることが、ウォークフォワードの再現性をタダで与えてくれます。同じ入力で必ず同じ結果になるので、
「パラメータを変えたのか、たまたまなのか」を切り分けられます。データ源や秘密情報の置き場所を替えても、
判断のコードは変わりません。

### 先読みを構造的に不可能にする

```
T日:
  1. 前日に出した注文を、T日の「始値」で約定させる
  2. T日の「終値」で建玉を評価し、資産曲線に1点打つ
  3. 戦略に「T日までのデータ」だけを渡し、注文を受け取る
  4. その注文は T+1日に持ち越す
```

**T日の引けで判断し、T+1日の寄りで約定する。** 同じ日の終値で約定させると「終値を見てから買った」ことになり、
成績が劇的に良くなります。最も入りやすく、最も気づきにくい先読みです。

戦略が受け取る `MarketView` は `as_of` より後の行に **触れられません**。規約ではなく、物理的にそうなっています。
FX も同じで、戦略に渡すのはその足までの配列だけです。

`tests/test_no_lookahead.py` の中心は次のテストです。**これが落ちたら、他の全部の結果を捨ててください。**

```python
def test_truncating_the_future_does_not_change_the_past():
    """期間を短く切っても、重なる部分の結果は完全に一致すること。"""
```

### FX の約定ルール

- 足の価格は仲値。買いは仲値 + 半スプレッド、売りは仲値 − 半スプレッドで約定し、さらに不利なずれを足す
- 1本の足で損切りと利確の両方に届いたら、**損切りが先** と見なす（有利な側を先にすると楽観的になる）
- 窓開けで逆指値を飛び越えたら、逆指値ではなく、より不利な始値で約定する
- ロスカットの価格は「有効証拠金 = 基準 × 必要証拠金」を仲値で解いて求める。届いたら **検証はそこで終わり**。
  窓開けでは入金額を超えて損をする（不足金）ことも再現する
- 日をまたがない（デイトレ）。必要証拠金が資金の80%を超える建玉は作らない

## 検証の方法

### ランダム比較（いちばん重要）

同じ保有期間・同じ銘柄数でランダムに売買した場合の分布を出し、戦略がその分布のどこにいるかを見ます。

```
戦略: sma_cross              +76.43%    +7.87%   -40.23%     0.47      68
ランダム（中央値）            +52.58%                         0.49
ランダム（5-95%）          -33.85% 〜 +159.67%

戦略の Sharpe は、ランダム分布の 48 パーセンタイルです。
  → ランダムと区別がつきません。この戦略に優位性があるとは言えません。
```

（合成データでの例）**+76%でも、ランダムの分布の内側なら優位性ではありません。**

### 多重検定の補正とロックボックス

パラメータや手法を N 通り試して一番良いものを選ぶと、その成績には「N回引いた中の最大値」という偏りが必ず乗ります。
真の Sharpe が 0 の戦略を N 個試したときに観測される最大 Sharpe の期待値（Bailey & López de Prado）と比べ、
超えていなければ「何もない」と区別がつきません。

- 試した回数は `state/experiments.jsonl` に **追記のみ** で残る（後から消すと N が嘘になる）
- 最後の期間（ロックボックス）は候補を絞るまで見ない。同じデータで二度評価しようとすると拒否される
- 探索に賢いアルゴリズム（ベイズ最適化など）は使わない。「何通り試したか」が曖昧になり、補正できなくなる

### Out-of-Sample とウォークフォワード

```
|--- 学習1 ---|-検証1-|
       |--- 学習2 ---|-検証2-|
              |--- 学習3 ---|-検証3-|

報告してよいのは 検証1 + 検証2 + 検証3 だけ
```

```bash
python scripts/validate.py holdout --strategy sma_cross --synthetic
python scripts/validate.py walkforward --strategy sma_cross --synthetic --train 250 --test 120
```

診断は **「有効」とは決して出しません。** 最良でも「否定はされていない」までです。
2年分（約490営業日）のデータでは窓が2つほどしか取れず、`判定不能（データ不足）` になります。

### 指標の読み方

もっとも信用してよいのは、勝率でも Sharpe でもなく **1取引あたりの期待値と、その t 値** です。
期待値 +1.85%、t = 0.86 なら、総リターンが +76% でも **優位性は「無い」と読むのが正しい**。
`core/metrics.py` は、取引数不足・|t| < 2・自己相関・コスト負けなどの警告を数字と一緒に返します。

## J-Quants の注意点

どれも間違えると例外にならず、静かに結果が歪みます。

- **銘柄一覧は必ず `date` 付きで取る。** 省略すると上場廃止の銘柄が消え、生存者バイアスが乗る
- **価格水準の判定は調整前の価格で。** 調整後は分割で過去が書き換わる（上の「見つけて直した偏り」）
- **財務は開示日時（`DiscDate` / `DiscTime`）で。** 決算期末を基準にすると、未公表の数字で売買したことになる
- **V2 はレスポンスが一律 `data`、認証は `x-api-key`。** キー名を間違えると「データがない日」として素通りする
- **レート制限を超えない速度で投げる。** 上限ぎりぎりだと 429 が続くので、余裕を持った間隔で投げる。
  取得済みの日はスキップするので、途中で止めても再開できる

## この先

1. **GMOコイン（外国為替FX）との接続**: API の最小注文数量の確認（1万円で取引できるか）、
   公開 API の実際の1分足での検証、約定の自動記録
2. **新しいデータの入手手段**: 実運用の候補には、遅れのないデータが要る
3. **前向き検証**: 少額で動かし、実際の約定と想定のずれを測る。増額の条件を満たすまで資金は増やさない

`core/costs.py` と FX のスプレッド・ロスカットの基準は、実測するまで **すべて仮定** です。

## 意図的に作っていないもの

- 自動発注（業者との連携と、安全装置の検証が終わるまで作らない）
- 機械学習（単純なルールで優位性が出ないうちは、複雑にしても過学習が増えるだけ）
- 国内株の信用取引・空売り（国内株は現物のみ。FX は売りから入れる）
- 配当（トータルリターンで評価したくなったら足す）
- 他人の資金の運用・第三者への提供（金融商品取引法上の登録が必要になる場合がある）
